# CLAUDE.md — Vigía

Reglas vinculantes para trabajar este repo. Contexto: `README.md` (arquitectura), `docs/DEPLOY.md` (producción), `docs/CALIBRACION.md` (calibración).

## Reglas duras

1. **Solo librería estándar de Python — cero dependencias.** La ingesta usa `urllib` + `sqlite3`; no hay `requirements.txt` y así debe seguir. NO agregues instalaciones pip (tampoco scipy: EMOS se implementa a mano, ver `docs/CALIBRACION.md`). Única excepción: el contenedor `push/` usa `pywebpush` (criptografía VAPID/aes128gcm imposible en stdlib); ningún otro componente puede agregar dependencias.
2. **Cache-busting obligatorio.** Si tocas `web/app.js` **o** `web/app.css`, sube el sufijo `?v=N` de **AMBOS** (comparten el mismo número aunque solo hayas tocado uno — el smoke test y `deploy.sh` exigen `app.js?v=N == app.css?v=N`) en `web/index.html` **y** en el array SHELL de `web/sw.js`, además de la versión del cache (`vigia-shell-vN`, contador independiente del ?v=N). Sin ese bump triple, Cloudflare y el service worker siguen sirviendo la versión anterior — y el deploy corta.
3. **CSP estricta** (`deploy/nginx.conf`): cualquier host o API nueva debe agregarse a `connect-src`/`img-src` o el navegador la bloquea. Nada de CDNs de terceros — Chart.js, Leaflet y las fuentes van vendorizados en `web/`.
4. **Los JSON de `web/` son generados, no editarlos a mano** (`status`, `verificacion`, `estaciones`, `aire`, `bias`, `avisos`, `sismos`, `incendios`, `alertas`, `volcanes`, `emergencia`, `remociones`, `tsunami_vias`, `tsunami_areas`, `marea`, `tsunami`, `cortes`, `farmacias`, `esval`, `combustible`, `crecidas` — veintiuno en total). Los produce la ingesta: en dev se escriben en `web/` (defaults de `ingesta/config.py`); en prod van a `/data` (envs del compose) y nginx los sirve por `alias`. Excepción: `web/comunas.json` (catastro INE de comunas) está versionado en el repo, no lo genera la ingesta. `cortes.json`, `farmacias.json` y `esval.json` son casos especiales: la ingesta no fetchea la red, lee un crudo subido por un satélite fuera del VPS (ver `satelite/README.md`). `combustible.json` está activo en producción con credenciales `CNE_EMAIL`/`CNE_PASSWORD` configuradas por env; queda dormido (0 estaciones) solo si faltan. `cortes.json` aplica además una guarda de plausibilidad en `ingesta/cortes.py`: si el ciclo nuevo trae <10% de comunas del último publicado (≥20), retiene el publicado con `parcial: true` (tope 90 min, `updated` nunca se falsifica) — no quitarla pensando que es un bug, existe porque la SEC devuelve ciclos degradados sin fallar el fetch. Al consultar `SEC ClientesAfectados/Get`: omitir el parámetro `hora` hace que el backend responda el snapshot de MEDIANOCHE con HTTP 200 (incidente real: reportó 13k clientes en vez de ~520k) — usar el flujo sin body (serie horaria) y tomar el último registro.
5. **Calibración con disciplina científica** (`ingesta/calibrate.py`): nunca aplicar bias sin gate de muestra mínima + shrinkage; nunca corregir `precipitation` ni `wind_direction`; ground truth = observaciones de estación (METAR/DMC), nunca reanálisis; descartar `lead <= 0` en verificación (es nowcast, infla la exactitud). Validación temporal (walk-forward), jamás k-fold aleatorio.
6. **Todo punto del archivo histórico ES una estación con observaciones** (invariante de `ingesta/config.py`) — no agregues puntos de pronóstico sin observación pareada.
7. **Cero secretos en el repo, en logs y en errores — el repo es PÚBLICO.** Nunca commitear credenciales, API keys, tokens, ni el usuario/IP de origen del VPS (el Cloudflare Tunnel existe para ocultarla; ya se filtró una vez y quedó en el historial). Los secretos van SOLO al `.env` de prod (chmod 600) y se leen por env. En código: un mensaje de error o `raw_payloads` jamás puede contener la URL con key/token (urllib incluye la URL completa en sus excepciones — descartar la query string antes de propagar), el enmascarado por `str.replace` de la key cruda NO sirve (urlencode la percent-codifica), y toda credencial viaja solo por https. Antes de commitear código que use un secreto: `git diff | grep -i "<fragmentos del secreto>"` debe dar vacío.
8. **Todo dato mostrado lleva su fecha visible.** Cada JSON generado incluye `"updated"` y cada capa/panel del frontend muestra "actualizado hace X" (helper `metaConFecha` en `app.js`); si la fuente entrega fecha por ítem (ej. precios CNE), se conserva y se muestra por ítem, con marca de "dato antiguo" cuando corresponde. Si el dato depende del satélite y está viejo, el JSON lleva `"stale": true` y la UI lo dice explícito. Honestidad de frescura = requisito, no adorno.
9. **Deploy SOLO con `bash deploy/deploy.sh`** — valida el export (versiones js/css sincronizadas) ANTES de copiar y corre los smoke tests después. Prohibido rsync/copy manual a `/opt/vigia` o reiniciar contenedores a mano como método de deploy. El export usa `git archive origin/main`: si el cwd es un subdirectorio del repo, archiva solo ese subárbol y el `rsync --delete` posterior arrasa el server (incidente real, sitio caído ~3 min) — usar siempre `git -C <raíz-del-worktree> archive` o verificar el export (debe incluir `docker-compose.yml`, `web/`, `deploy/`) antes de sincronizar.
10. **Slack (`ingesta/watchdog.py`, `push/send.py`) es SOLO para eventos de zona/emergencia y fallas reales — cero mensajes informativos rutinarios** (preferencia explícita del usuario). No agregar resúmenes, digests ni notificaciones informativas nuevas sin pedido explícito. Corolario: las notificaciones del deploy automático NO van a `#vigia`, van a `#status-deploy` (canal del flujo de deploy del fleet).
11. **Deploy automático de madrugada** (`scripts/deploy-cron.sh`, crontab horario con gate a las **03:20 hora de Chile**): si `origin/main` avanzó desde el último deploy, corre `deploy/deploy.sh origin/main` — el mismo script de la regla 9, sin LLM de por medio. El merge del PR a main ES el sign-off; el marker (`~/.local/state/vigia-last-deployed`) solo avanza si el deploy y su smoke test salieron en verde. Log en `~/.local/state/vigia-deploy-cron.log`; flags de test `FORCE_HOUR=1` y `DRY_RUN=1`. El horario es parte del escalonado del fleet (clima 03:20 · ERP Rollitos 04:00 · rollitos.cl 04:40 · ERP iktus 05:20): dos deploys pesados a la misma hora se pelean la CPU y el disco de la VM.
12. **Guarda de producción** (`scripts/hooks/prod-guard.sh`, hook `PreToolUse` de `.claude/settings.json`): cualquier comando que toque `/opt/vigia`, los contenedores `clima-*` o `deploy/deploy.sh`, y que no sea inequívocamente de solo lectura, pide confirmación explícita. Los diagnósticos (`docker logs`, `cat` de JSON, `docker compose ps`) pasan sin molestar.

## Comandos

```bash
python3 ingesta/run.py --all         # corrida completa local (obs + pronósticos + verificación + calibración)
python3 ingesta/run.py --hazards     # sismos + incendios + alertas + volcanes + tsunami + cortes
python3 ingesta/run.py --emergencia  # infraestructura de emergencia (semanal)
python3 -m http.server 8123 -d web   # frontend local
docker compose up -d                 # prod: nginx + contenedor cron de ingesta
```

No hay suite de tests unitarios: la validación es empírica — verificación MAE/RMSE/bias contra observaciones y holdout temporal en `ingesta/bootstrap_hist.py`. Sí existe un smoke E2E de Playwright en `deploy/smoke_browser.py` (corre en cada deploy) con perfil limpio por defecto — NO cubre capas restauradas desde `localStorage` (`sinoptica.capas`), que ejecutan una ruta de arranque distinta y ya causaron un `ReferenceError` fatal en prod (TDZ, PR #93). Al tocar `CAPAS`, loaders lazy o el arranque de `web/app.js`: sembrar `localStorage` con `add_init_script` antes de cargar y escuchar `pageerror` (ver `check_capas_restauradas`, cubre las 15 capas). Las claves de `localStorage` siguen siendo `sinoptica.*` (nombre pre-rebrand) a propósito — cambiarlas borraría las preferencias guardadas de los usuarios; no "corregirlas".
